# yiA 测试方案

> 配套 PRD §10 工程规范。原则：**测试跟着风险走**——单人自用项目，不为覆盖率写测试，只为"坏了会疼的地方"写测试。

## 1. 测试分层

| 层 | 形式 | 运行方式 | 引入时机 |
|---|---|---|---|
| L1 自检 | assert 脚本，无框架 | `cd yiA && npm test` | M1 已有（`yiA/src/memory/l2/selfcheck.ts`） |
| L2 单测 | `node:test`（Node 内置，不引第三方） | `cd yiA && npm test` | M2 起对核心模块补充 |
| L3 加载检查 | SDK 创建会话验证扩展/工具注册，不调 LLM | `cd yiA && npm run loadcheck` | M1 已有（`yiA/scripts/loadcheck.ts`） |
| L4 E2E 冒烟 | `pi -a -p "记住…"` / `pi -a -p "recall …"` 真实走一遍 | 手动或脚本 | M1 已验证 |
| L5 性能基准 | 生成 1 万条假数据跑检索，计时 | `npm run bench` | M2（配 PRD <1s 基线） |

**提交前最低门槛：在 `yiA/` 目录下 `npm test` + `npm run loadcheck` 全过。**

## 2. 各里程碑测试项

| 里程碑 | 必测项 | 层 |
|---|---|---|
| M2 记忆完整 | L1 画像读写往返；L3 FTS5 索引同步（Pi 会话 JSONL → SQLite）；门控召回的阈值边界（分数不够不注入）；ContextPack 注入后系统提示包含画像；refine 更新不破坏原条目 | L2 |
| M3 提醒调度 | 自然语言 → cron 表达式解析正确性；jobs.json 重启不丢；单任务异常不影响下个任务；错过的时间点补发策略 | L2 |
| M4 微信接入 | 适配器与 ClawBot webhook 协议往返；掉线重连；凭据不落日志/会话 | L2 + L4 |
| M5 TUI 打磨 | 跨渠道路由（同一 send_message 到 TUI/微信） | L4 |
| M6 Web | HTTP+SSE 接口冒烟；记忆浏览/编辑不破坏 frontmatter | L4 |
| M7 图谱 | 节点/边规模在 1 万条记忆下的渲染性能 | L5 |

## 3. 性能基准（对应 PRD §7）

- **检索**：1 万条记忆，recall P95 < 1s（`npm run bench`，生成假数据脚本放 `yiA/scripts/bench.ts`）
- **冷启动**：`time pi -p "hi"` < 3s（排除 LLM 响应时间，量进程启动到扩展加载完成）
- **微信端到端**：< 5s（M4 起人工计时，连续 10 条取均值）

## 4. 异常路径测试（对应工程规范 §10.2）

每个 IO 边界至少一条"破坏性用例"：

- 条目文件损坏（非法 frontmatter）→ all() 跳过不崩 ✅ 已有
- 条目文件运行中被删除 → parse 返回 null 跳过 ✅ 已有
- runtime/ 目录被删 → L2Store 构造时 mkdirSync 自动重建 ✅ 已有
- jobs.json 损坏 → M3 必测：备份后降级为空任务列表 + warn 日志，不崩
- L3 SQLite 会话索引损坏 → M2 必测：从会话 JSONL 重建（仅限可重建的会话索引；书籍库含原件，不能当缓存删除）
- ClawBot 侧车无响应 → M4 必测：超时 + 重连 + TUI 状态提示降级

## 5. 回归纪律

- 任何改动 `yiA/src/` 的提交，跑 L1+L3 再 commit
- 触及 M2-M7 核心逻辑（门控、调度、通道）的提交，额外跑对应里程碑的必测项
- 性能敏感改动（检索、注入）跑一次 bench 记录数字到 commit message

## 6. 书籍库回归（已实现）

`yiA/tests/books.test.ts`、`book-api.test.ts`、`book-tools.test.ts` 以及 `book-fixtures.ts` 使用合成电子书，不分发用户原书、不调用在线模型。
覆盖文字编码、中文单字/多词与英文查询、PDF 元数据/页码/密码/无文字、EPUB spine/实体/脚本、ZIP 路径/解压体积、损坏文件、大小上限、事务回滚、跨连接即时可见、跨进程并发去重、原件下载与删除级联清索引、坏库保留、同源/Host/类型检查，以及只读工具的检索和前后文出处。

全套现为 87 项，另用 loadcheck 确认三个书籍工具实际注册。新增书籍及其 HTTP 调用链通过严格 TypeScript 检查。
浏览器验证导入/去重/检索/阅读/删除/刷新、引用跳转、文本不执行 HTML、请求乱序保护和键盘关闭弹窗；五页、明暗主题、1440/1024/390/320 宽度检查溢出与标题几何。
用户提供的 418 页 PDF 仅在临时数据目录验证解析、中文检索、原件校验与工具，不自动写入正式书架；截图只展示合成正文。
不把模拟聊天引用跳转当成实际在线模型问答验证；此轮未运行付费生成、扫描件 OCR 或 Windows/macOS 实机验证。
详情见 [书籍导入与全文检索](书籍导入与全文检索.md)。
