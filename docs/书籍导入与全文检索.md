# 书籍导入、原件阅读与全文检索

## 使用方式

打开网页「书籍」页，点「＋ 导入」，选择文字版 PDF、EPUB、TXT 或 Markdown。
点击书名后，右侧默认是原件阅读器，不再把检索用的纯文字当成阅读页面。

- PDF：本地 PDF.js 绘制原版页面，保留字号、版式和图像；支持选择文字、翻页、输入页码、80%–200% 缩放及适合宽度。资源随应用提供，不使用在线 PDF 查看服务。
- EPUB：按原书阅读顺序展示章节 HTML、标题、强调、样式和包内图片/字体，章节下拉框与书内章节链接可跳转。文档在无脚本沙箱中显示，禁用脚本、表单、外部链接和远程资源。
- Markdown：显示标题层级、段落、强调、列表等结构；原始 HTML 只作为文字显示，不执行。单文件引用的外部图片不会自动联网加载。
- TXT：保留原文，带真实行号，每 200 行一屏；TXT 本身没有标题样式，不猜测标题。

「展开阅读」收起书架；手机打开书籍时自动进入阅读模式，点「返回书架」恢复列表。阅读比例在本浏览器保存。
「下载原文件」取回数据库中按字节保存的原件副本，不修改上传前的文件。

左侧按关键词搜索全部书籍或某一本书，多个词用空格分隔，要求在同一索引片段内全部命中。
点击命中后，PDF 跳到对应文件页，EPUB 跳到对应章节，TXT/Markdown 按源文件行定位；能可靠匹配时标记对应文字。
重复原文不能唯一确认时，只定位到已知页/节/行并显示提示，不把猜测的位置称为精确命中。
这是关键词全文检索，不是语义向量检索；没有命中时，可换词或分开搜索多个概念。

「查看检索文字与提取提示」是独立折叠层，展示供模型核对的纯文字片段及扫描页/少字页警告。
手动翻到其他原书页面后，旧片段引用不继续冒充当前页引用。阅读原书不表示扫描页已经进入文字索引。

升级后重启 Web；已打开的 TUI 用 `/reload` 加载扩展，微信 CLI 下次请求加载新工具。
对话里可以说「在我导入的某本书里查一下目标设定」：`list_books` 找编号、`search_books` 找关键词、`read_book_passage` 核对前后文。
模型仍然读取数据库中的文字片段，不自动接收整个原件，也不会为了阅读原书调用模型。

回答须注明书名、原文位置和 `bk_完整编号:片段号`；网页点击引用同样会打开原件并定位。
PDF 页码是文件页序，不保证等于印刷页码；EPUB 没有固定页码，用章节顺序、原文标题和包内文件路径定位。

## 存储与无损升级

数据仍在仓库根 `runtime/books/library.db`，与 L1/L2/L3 独立：

- `books`：书籍元数据、SHA-256、原件 `source BLOB`；原件没有移出数据库。
- `passages`：检索用的纯文字、出处、词元，以及新增的 `anchor TEXT`（结构化定位 JSON）。
- `book_fts`：索引 `passages.tokens`，通过 rowid 关联片段；不是原书阅读内容，也不是向量数据库。

定位包含 `kind`、PDF 的 `page`、EPUB 的 `section/path`、文字书的 `line/endLine`，新片段还保存去空白/NFKC 后的 `offset`。
浏览器用位置和原文片段核对，再标记原件中的文字。索引切片仍约 1200 字、重叠约 160 字，不改变旧片段的编号或正文。

旧数据库首次打开时，先用 SQLite `VACUUM INTO` 生成包含 WAL 已提交数据的一致性备份，位于：
`runtime/books/backups/library-before-reader-随机编号.db`。
备份成功后，事务新增 anchor 列，按旧出处回填已有页/节/行信息。未知位置标记 unknown，不编造字符偏移。
旧书无需重新上传；原件、书籍 id、片段 id、正文和全文索引均保留。备份失败时停止升级，不覆盖旧库。

这不是可以随手删掉重建的缓存。损坏时保留原数据、显示错误；备份仍需覆盖整个 books 目录（包含活动时可能存在的 -wal/-shm）。
删除一本书只删正式库里的指定原件副本、正文和索引，不删上传前的文件、迁移备份、聊天记录或另存的读书笔记，不承诺磁盘安全擦除。

## 支持范围与隐私

单本最多 50 MiB、约 500 万字符、PDF 最多 2000 页、EPUB 最多 2000 个正文文档。
需要密码的 PDF 请先在本机解密；扫描件导入仍需先 OCR，完全无文字的版本会拒绝，部分提取有警告。
不含 OCR、DRM 解锁、向量检索、自动摘要或 PDF 重排；原书中的复杂排版/字体可能因浏览器支持存在差异。
PDF 链接注释与脚本不执行；EPUB 原书脚本、表单、外部资源被清理并受 iframe sandbox 和 CSP 双重限制，不能把书籍 HTML 注入应用主 DOM。

同一服务进程一次只导入一本。解析子进程堆上限 384 MB、两分钟超时，ZIP 资源有路径、解压体积和 CRC 校验，不落地展开。
阅读器只保留最近一本非 PDF 的解析缓存；TXT 按屏生成 HTML，不预先生成整本书的行标签。PDF 按页渲染，原件支持 HTTP Range 读取。

导入、网页检索、原件阅读均在本机。只有用户对话查书时，命中片段/前后文才发给当前模型，并随会话记录保存。
原文始终是参考资料，不是可执行指令。日志不记录书名、检索词或原文。
书籍数据、预览及资源接口均校验本机 Host/端口与 Origin；PDF.js 资源只暴露安装包内的白名单文件。
本机待导入的 `book/`、运行数据和自动备份均被 Git 忽略，不随源码分发。

## 实现入口与接口

`yiA/src/books/store.ts` 负责 SQLite、切片、索引与升级；`anchors.ts` 负责定位格式；`parse.ts` 只做检索文字解析。
`epub.ts` 共用安全 ZIP/EPUB 读取；`preview.ts` 从原件生成隔离阅读文档。
`yiA/src/server/book-routes.ts` 挂到既有 `createYiaServer`，没有第二套服务器。
`yiA/web/js/books.js` 负责书架与搜索，`book-reader.js` 负责原件阅读，模型继续使用 `src/agent/book-tools.ts` 的只读工具。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/books` | 书架元数据，不含 BLOB |
| POST | `/api/books/import?name=文件名` | 二进制上传；201 新导入，200 已存在 |
| GET | `/api/books/search?q=关键词&bookId=可选编号` | 最多 20 个索引命中 |
| GET | `/api/books/:id/passages/:n` | 检索文字、anchor 和书籍元数据 |
| GET | `/api/books/:id/original` | 原件附件下载 |
| GET | `/api/books/:id/content` | PDF inline 原件，支持单范围 Range/206/416 |
| GET | `/api/books/:id/reader-info` | 非 PDF 章节/阅读单元目录与源文件行范围 |
| GET | `/api/books/:id/reader?unit=n` | 经清理的无脚本阅读文档 |
| GET | `/api/books/:id/assets/包内路径` | 本书图片、CSS 和字体，不提供可执行文件 |
| GET | `/api/books/assets/pdfjs/白名单路径` | 本地 PDF.js 核心、worker、字体/CMap/WASM |
| DELETE | `/api/books/:id` | 事务删除指定书籍及索引 |

Node ≥22.13，无需额外 Python、OCR 程序或外部数据库服务。
