# yiA 产品需求文档（PRD）

> 版本：v0.2（草案）｜ 状态：TUI 阶段启动
> 定位：**部署在个人电脑上的"第二大脑"**——对话式存储信息，按需提炼知识，主动提醒事务。

---

## 1. 背景与目标

### 1.1 问题

- 灵感转瞬即逝：想到一个好 idea，没有低摩擦的入口立刻存下来，事后想不起来。
- 琐事淹没：一天处理的事太多，重要事件、会议、承诺散落在聊天记录和脑子里，容易遗忘。
- 信息存了等于没存：用笔记软件存进去的东西，检索成本高、缺乏关联，很少再被"提炼"出来。

### 1.2 产品目标

把 yiA 做成一个**常驻个人电脑、可对话的第二大脑**：

1. **存得快**：一句话（或一段话）丢给 yiA，就完成存储、归类、关联。
2. **取得准**：随时用自然语言提问，yiA 从记忆库中检索并**提炼**出答案（不是原样翻找，而是综合多个记忆条目给出结论）。
3. **会主动**：定时提醒重要事件、会议、到期事项；在合适的时机把相关的旧记忆"推回"给用户——**TUI 时期即可推送到微信**。

### 1.3 非目标（当前版本明确不做）

- ❌ 多用户 / 团队协作 / 云端同步（单机单人）
- ❌ 移动 App（预留）
- ❌ 语音交互（预留）
- ❌ 修改 Pi SDK 内核

## 2. 用户与使用形态

**目标用户**：开发者/知识工作者本人（作者自用优先，单人部署在自己的电脑上）。

**分期原则：功能能力在 TUI 期全部做齐（含微信）；Web/App 只补 TUI 做不了的"可视化与界面"部分。**

| 阶段 | 形态 | 范围 | 状态 |
|---|---|---|---|
| **Phase 1（TUI）** | 终端对话 + 微信渠道 | **全部功能能力**：记忆系统、提炼、提醒调度、微信对话与提醒推送、记忆管理命令 | 本期重点，做成熟 |
| Phase 2（Web） | 本地 HTTP 服务 + 浏览器 UI | 仅 UI 层增值：知识库浏览界面、**知识图谱可视化（对齐 inno-agent wiki 图谱）**、提醒/记忆管理页面 | TUI 成熟后启动 |
| Phase 3（App，远期） | 移动端 | 图谱增强、若 Web 阶段图谱降级则移入本阶段 | 远期 |

> 渠道原则：所有交互入口（TUI/微信/Web）共享同一个记忆库和同一个 Agent 运行时，渠道只是不同的"输入输出适配器"——所以微信可以也应该在 TUI 期就接入。

## 3. 核心场景（验收基准）

### 场景 A：灵感捕获

> 用户：我刚想到一个主意，用本地小模型给截图做自动打标签，然后按语义搜索相册。
> yiA：（存入记忆库，自动打上 #idea #本地模型 #图像 标签，与已有的"相册整理"记忆建立关联）已记下。它和你 6 月记的"相册整理工具"想法相关，要合并成一条吗？

**验收**：从开口到确认存好 ≤ 10 秒；不需要用户指定目录/文件名/分类。

### 场景 B：事项记录 + 定时提醒（TUI 期即含微信推送）

> 用户（在终端或微信里）：周四下午 3 点要和房东视频看房，提前 1 小时提醒我。
> yiA：已记录"和房东视频看房（周四 15:00）"，将在周四 14:00 提醒你。

周四 14:00，**手机微信收到**：
> yiA：⏰ 1 小时后：和房东视频看房。相关：你上周记过"房租合同 8 月底到期"。

**验收**：人在外面、电脑开着，手机微信准时收到提醒。

### 场景 C：知识提炼（第二大脑的核心价值）

> 用户：我之前存过好几个关于时间管理的想法，帮我汇总一下。
> yiA：（检索 → 跨条目综合 → 输出提炼结果，附来源链接）你一共存过 4 条相关记忆……综合来看你倾向的两个方向是……其中"两分钟原则"和 3 月那条"打断成本"笔记有冲突，建议……

**验收**：能跨多条记忆综合回答，且能给出每条结论的来源记忆条目。

### 场景 D：随时随地微信对话

> 用户（微信）：我上次说想学的那个东西是什么来着？
> yiA：（微信内回复，检索自同一记忆库）你 7 月 2 日记的是"想系统学 Rust，先从所有权机制入手"……

**验收**：微信对话与 TUI 对话共享记忆，任意一端存的内容另一端可查。

## 4. 功能需求

### 4.1 F1 记忆系统（借鉴 inno-agent 三层架构）

| 层 | 内容 | 生命周期 | 存储 |
|---|---|---|---|
| **L1 用户画像** | 身份信息、常驻事项、偏好、正在进行的项目 | 天~周级更新 | JSON 文件 |
| **L2 知识库** | 沉淀的知识条目：idea、笔记、事实、决策及其**关联** | 长期沉淀 | Markdown 条目文件 + 关联索引 |
| **L3 会话记忆** | 历史对话的全文索引，跨对话检索 | 中期（可归档清理） | SQLite FTS5（叠加在 Pi 会话 JSONL 上） |

功能点：
- **F1.1 快速捕获**：单条工具调用完成"原文 + 自动标签 + 时间戳 + 来源会话/渠道"的持久化。
- **F1.2 自动关联**：新记忆入库时检索相关旧记忆，建立双向链接（先规则/BM25 相似度，后期可选图谱聚类）。
- **F1.3 混合检索**：BM25（L2/L3）起步，预留向量检索升级位。
- **F1.4 阈值门控召回**：检索结果按相关性阈值决定是否注入上下文，宁缺勿滥。
- **F1.5 知识提炼**：多条记忆 → 综合回答 + 来源引用（场景 C）。
- **F1.6 记忆管理**：TUI 命令查看/编辑/删除记忆条目、查看某条目的关联列表（Web 期升级为图谱视图）。

### 4.2 F2 提醒与调度

- **F2.1 自然语言创建提醒**："周四下午 3 点…提前 1 小时提醒我" → cron/一次性定时任务。
- **F2.2 任务持久化**：jobs.json + runs.jsonl（借鉴 inno-agent），重启不丢。
- **F2.3 触发与回推**：到点触发 → **按记录时的用户偏好回推到指定渠道**（微信优先，其次 TUI 通知）。
- **F2.4 事项清单**：重要事件/会议/TODO 的记录与查询（作为一类特殊记忆条目，带时间属性）。

### 4.3 F3 对话与 Agent

- **F3.1** 基于 Pi SDK `AgentSession`，TUI 交互模式。
- **F3.2 工具集**（第一期）：`remember`（存）、`recall`（查）、`refine`（提炼综合）、`set_reminder`、`list_reminders`、`memory_manage`、`send_message`（跨渠道发送/推送）。
- **F3.3 系统提示词注入**：每轮注入 L1 画像摘要 + L3 门控召回（借鉴 inno-agent 的 ContextPack 模式）。
- **F3.4 会话树**：直接复用 Pi 原生会话管理（分支/续聊）。

### 4.4 F4 微信渠道（**TUI 期实现**）

- **F4.1 ClawBot 侧车**：部署 `@tencent-weixin/openclaw-weixin`（腾讯微信团队官方插件，走官方开放 iLink API），扫码登录个人微信。
- **F4.2 clawbot-channel 适配器**：yiA `ChannelRegistry` 收 Webhook 消息 → 喂给 AgentSession → 调发送 API 回复。
- **F4.3 提醒推送**：调度器到点 → 经微信渠道回推到手机（场景 B）。
- **F4.4 渠道一致性**：微信与 TUI 共享记忆库与会话归属（同一用户）。
- **限制**：仅私聊（ClawBot 插件不支持群聊）；个人号接入风险低但非零。

### 4.5 F5 Web 形态（Phase 2，仅 UI 增值）

> TUI 期已具备全部能力，Web 只做"看得见"的部分。

- **F5.1** 本地 HTTP 服务 + SSE 流式对话（复用同一 Agent 运行时）。
- **F5.2 知识库浏览**：记忆条目列表 + 详情 + 全文搜索 + 编辑。
- **F5.3 知识图谱视图**：条目关联的可视化（**对齐 inno-agent 的 wiki 图谱**：Cytoscape 渲染、点击节点看条目、点边看关系）。**若实现困难 → 降级为"关联列表"视图，图谱移到 App 阶段**。
- **F5.4** 提醒管理页面。

### 4.6 F6 后续渠道（预留）

- 飞书/QQ：`ChannelRegistry` 预留扩展位，微信适配器跑通后照抄模式。

## 5. 技术方案（概要）

### 5.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| Agent 内核 | Pi SDK `@earendil-works/pi-coding-agent`（TS） | 不改内核，扩展工厂 + 工具注册 |
| 主体 | **TypeScript**（Node ≥ 20.6） | Agent 运行时、记忆系统、调度器、TUI、Web 服务、渠道适配 |
| 辅助 | **Python** | 文档/内容解析、后续向量检索/语义处理的独立小服务（gRPC/HTTP 调用），不在主链路上 |
| TUI | Pi 原生交互模式 + 自定义 Extension | 起步成本最低 |
| L2 存储 | Markdown 条目文件 + SQLite/BM25 索引 | 人类可读、git 可备份 |
| L3 存储 | SQLite FTS5 | 借鉴 inno-agent |
| 微信 | **ClawBot 侧车（`@tencent-weixin/openclaw-weixin`）+ 自写 Webhook 适配器** | 腾讯官方开放接口，合规风险最低 |
| Web（P2） | 原生 node:http + SSE；前端 React + Cytoscape（图谱） | 对齐 inno-agent 技术选型 |

### 5.2 架构

```
交互入口        TUI + 微信 (P1) → +Web (P2) → App (远期)
                     ↓
应用层          记忆编排 · 提醒调度 · 渠道适配 (ChannelRegistry)
                     ↓
Agent 运行时    Pi AgentSession + yiA 扩展（工具注册 + 提示词注入，内核零改动）
                     ↓
记忆           L1 画像 (JSON) · L2 知识库 (Markdown+索引) · L3 会话 (SQLite FTS5)
```

### 5.3 目录结构（已实施，M1 起生效）

```
~/yiA                  ← 项目根（git 仓库）
├── AGENTS.md                Agent/协作者说明（pi 发现位置，留根）
├── docs/                    产品与工程文档（PRD、测试方案等）
├── .pi/extensions/yia.ts    pi 自动发现的薄加载器（留根）
├── runtime/                 本地数据（l2 条目/日志/任务，gitignored，可整体备份）
└── yiA/                     ★ 全部开发代码（代码边界，数据永不进此目录）
    ├── package.json         npm test / loadcheck 等命令在此目录跑
    ├── src/
    │   ├── agent/           yiA 扩展工厂、工具、系统提示词
    │   ├── memory/          l1/ l2/ l3/（分词/BM25/存储按模块分文件，中文注释）
    │   ├── scheduler/       提醒任务 (M3)
    │   ├── channels/        tui / clawbot(微信) (M4) / (预留 feishu、qq)
    │   ├── server/          (P2) HTTP + SSE
    │   ├── logger.ts        统一日志入口 (M2)
    │   └── runtime.ts / config.ts
    ├── scripts/             loadcheck / bench 等检查脚本
    ├── yia-ui/              (M6) Web 原型（纯静态，桌面优先，已过一轮设计审查）；P2 起 React 前端沿用此目录或另立
```

**职责分离约定**：`yiA/` 只放代码；根目录 `runtime/` 只放数据（便于整体备份）；`docs/` 只放文档；`.pi/` 是 pi 的发现位置，仅保留薄加载器指向 `yiA/src/agent/`。

## 7. 非功能需求

- **本地优先**：全部数据落在本机，无云依赖；LLM 可配置任意 openai-completions / anthropic-messages 端点（含本地模型）。
- **隐私**：记忆库明文可读（Markdown），用户可随时查看、导出、删除；不出本机（LLM API 除外，且可选本地模型）。
- **可备份**：runtime/ 目录整体可 git/网盘备份。
- **性能**：记忆条目 ≤ 1 万条时，检索响应 < 1s；TUI 冷启动 < 3s；微信消息端到端响应 < 5s。
- **健壮性**：提醒任务重启不丢；单条记忆损坏不影响整体；ClawBot 侧车掉线自动重连并有 TUI 状态提示。
- **常驻**：TUI 期即要求后台常驻运行调度器与微信侧车（用户电脑开机期间）。
- **安全**：扩展工具限制文件写入范围在 runtime/ 内（参考 inno-agent workspace-path-guard）；微信凭据/token 不入库不进会话记录。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 记忆越攒越多，检索变噪 | 阈值门控 + 定期归档 + 后续向量检索升级位 |
| 微信个人号接入不稳定/有封号风险 | 采用腾讯官方 ClawBot 插件 + 侧车进程隔离；仅私聊；掉线自动重连；微信失败时提醒降级到 TUI 通知 |
| ClawBot 插件与 OpenClaw 版本耦合 | 锁定 OpenClaw + 插件版本；适配器隔离协议变化 |
| Pi SDK 版本升级破坏扩展 | 锁定版本 + 只用公开 ExtensionAPI（inno-agent 已验证此路径可行） |
| 后台常驻依赖用户电脑开机 | 单人自用可接受；远期可选家用小主机/服务器部署 |

## 9. 成功指标（自用阶段）

- 日均主动存入 ≥ 3 条记忆（说明"存得快"成立）
- 每周 ≥ 5 次 recall/refine 使用（说明"取得准"成立）
- 微信提醒零漏发（说明"会主动"成立）
- 微信端使用占比 ≥ 30%（说明"随时随地"成立）
- 连续使用 4 周后仍愿意用（留存即真理）

## 10. 工程规范（日志 / 异常 / 测试）

### 10.1 日志规范

- **统一入口**：M2 落地 `yiA/src/logger.ts`，全项目禁用散落的 `console.log`（调试时可临时用，提交前清除）
- **落盘**：`runtime/logs/yia.log`，按天滚动，只保留最近 14 天（自实现文件流，不引日志库）
- **级别**：`error` / `warn` / `info` / `debug`，默认 `info`，环境变量 `YIA_LOG_LEVEL` 可调
- **必记**：工具调用（名称 + 耗时 + 成败，不含正文）、调度器触发、微信通道事件（连接/断开/重连）、未捕获异常
- **禁记**：记忆正文全文（只记条目 id 与长度）、任何凭据/token、会话原文——隐私红线
- Pi 自身的会话记录（JSONL）由 Pi 管理，yiA 不重复记录

### 10.2 异常处理规范

- **工具边界必指**：`remember`/`recall` 等扩展工具的 execute 必须 catch 并把错误信息作为结果返回给模型，不允许异常穿透导致 agent 循环中断
- **入口兜底**：扩展工厂内的初始化代码不得抛出——加载失败要降级（如 L2 不可用时提示工具不可用），不能拖垮 pi 启动
- **数据容错**：单条记忆损坏跳过不崩（已实现）；jobs.json 损坏降级为空表 + warn（M3）；SQLite 索引损坏可从会话 JSONL 全量重建（M2）
- **任务隔离**：调度器单任务异常只记 error，不影响后续任务（M3）；微信发送失败降级到 TUI 通知（M4）
- **禁止空 catch**：捕获后至少 `logger.warn`，吞错误即埋雷
- **进程级兕底**：`uncaughtException` / `unhandledRejection` 记入 error 日志，不允许静默退出

### 10.3 测试规范

详见 **`docs/测试方案.md`**（测试分层、各里程碑必测项、性能基准、异常路径用例）。核心纪律：

- 提交前 `npm test`（L1 自检）+ `npm run loadcheck`（L3 加载检查）必过
- 单测用 Node 内置 `node:test`，不引第三方测试框架
- 每个 IO 边界至少一条破坏性用例（文件损坏/删除/目录被删）
